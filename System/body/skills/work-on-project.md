# Working on a Development Project

Use when the owner asks for help understanding, planning, changing, or reviewing
a software project.

1. Read the project instructions and identify the task's relevant files.
2. Ask for or inspect the smallest useful project context; do not scan unrelated
   personal or reference data.
3. Confirm existing APIs, conventions, and test commands before proposing
   implementation details.
4. Make only requested, scoped changes, using the host's file permissions and
   safeguards.
5. Run the narrowest relevant validation available.
6. Summarize changed files, checks, and known limitations.

Do not copy secrets or confidential project data into notes or examples.
